# xPoster 使用说明

这份说明写给第一次使用 Chrome 扩展的人。

## 1. 安装 xPoster

推荐安装方式：

1. 打开 [xPoster Chrome Web Store 页面](https://chromewebstore.google.com/detail/xposter/iimkimodgdjnnmdopeolboakhjmhfbbj?authuser=0&hl=zh-CN)。
2. 点击 **添加至 Chrome**。
3. 使用应用商店版本，它会持续获得功能更新和体验完善。

开发者源码安装：

1. 下载或 clone xPoster。
2. 打开 Chrome。
3. 在地址栏输入 `chrome://extensions`。
4. 打开右上角 **开发者模式**。
5. 点击 **加载已解压的扩展程序**。
6. 选择 xPoster 文件夹，也就是包含 `manifest.json` 的文件夹。

普通用户建议走应用商店安装，不需要理解源码安装。

## 2. 准备 Markdown 草稿

可以用任何 Markdown 编辑器。一个最小示例：

```markdown
---
title: 我的第一篇 X 文章
---

# 如果上面有 title，这个标题会进入正文

这里是一段正文，带有 **加粗** 和 [链接](https://example.com)。

- 第一点
- 第二点

![图片说明](image.png)
```

封面取自 frontmatter 里的 `cover:`。没写时，紧跟在标题下面的那张图会成为封面，正文里不再重复。位于文章中间或后面的图片保持在你放的位置。

仓库里也带了一个测试草稿：

```text
fixtures/live-x-smoke.md
```

## 3. 打开 X 文章编辑器

1. 在 Chrome 里登录 X。
2. 打开 `https://x.com/compose/articles`。
3. 新建文章，或打开你想填充的文章草稿。

xPoster 需要一个已经打开的 X Article 页面，因为它会填充当前页面里的编辑器。

## 4. 打开 xPoster

从 Chrome 工具栏或侧边栏打开 xPoster。

## 5. 放入草稿

- 直接粘贴 Markdown，或点击 **导入本地文件** 选择 `.md` 文件。
- 也可以点击 **样例** 先试用，或切换到 **预览** 查看转换结构。

## 6. 点击发布

载入草稿后，主按钮固定显示 **发布**。点击一次，xPoster 会自动检查当前 X 文章编辑器、图片上传能力和图片权限，再写入草稿，无需单独点击检查。

Markdown 使用相对路径本地图片（例如 `./images/photo.png`）且尚未选择目录时，会在 X 页面弹出文件夹选择提示。选择包含 `images` 的上级文件夹，流程会自动继续。取消选择会停止本次操作，不会写入 X。

路径以 `../` 或 `../../` 开头时，插件会在读取图片时自动忽略这些前缀。例如 `../40_Assets/cover.png` 仍选择包含 `40_Assets` 的上级目录。原 Markdown 不变，插件不会访问所选目录之外的文件。

远程图片如需权限，Chrome 会请求授权图片来源网站。允许后自动检查下载并继续。没有图片时不会要求选择文件夹；Markdown 表格会自动转成图片，因此仍需要 X 的上传能力。

## 7. 查看错误

失败时，主按钮下方直接显示错误和诊断记录。点击 **复制错误信息**，即可复制给维护者排查。复制失败时会选中错误文字，可手动复制。详细检查和记录保留在 **设置** 中。

此处的 **发布** 会把内容写入 X 草稿。公开发布仍需在 X 内确认。

## 8. 在 X 里检查

发布前请检查：

- 标题是否正确。
- 文本格式是否正确。
- 图片是否出现。
- 表格是否清晰。
- 推文嵌入是否正确。
- 代码块和分割线是否能接受。
- 没有残留 `__XPOSTER_` 之类的占位文字。

xPoster 不会替你点击发布。你必须自己确认后，在 X 里手动发布。

## 常见问题

### Chrome 说这是解包扩展

源码安装时这是正常的。普通用户建议安装 Chrome 应用商店版本。

### 检查文章时说找不到编辑器

请打开或新建一篇真正的 X Article 草稿。只停留在文章列表页不够。

### Chrome 询问图片网站权限

如果你信任这个图片来源，可以选择允许。xPoster 需要读取图片文件，才能上传到 X。

### 本地图片没有导入

请选择包含这些图片的本地文件夹。相对路径如 `./images/photo.png` 只有在 xPoster 能读取对应文件夹后才可用。

### 上传图片时正文消失了

X 偶尔会在图片上传完成时换回较早的编辑器状态，导致刚写入的正文被丢掉。xPoster 会先写入标题和正文，等 X 保存完（Markdown 里有标题时才能检查这一点），再一张一张上传图片，每张传完都会重新检查。X 仍然替换了文章时，xPoster 会自动把正文放回去。如果发布报错 “X replaced the article body …”，请先在 X 里清空草稿、刷新标签页，再点击 **发布**。反复出现时点击 **复制错误信息**，报告里会显示是哪一次上传触发的。

### 图片位置和 Markdown 不一致

每张图片上传成功后立刻放到它的位置，最后 xPoster 会拿成稿和 Markdown 对一遍。如果仍有图片不在原位，发布会报错 “Some images are not where the Markdown puts them”，并指出是哪一张。请点击 **复制错误信息** 并把报告发来：其中的 `trace` 按时间记录了 X 做了什么，能说明图片为什么被挪走。

### 同一张图出现了两次

X 上传较慢、迟迟才完成，或者重新载入了较早的文章副本时，可能为 xPoster 已放好的图片多加一个块。xPoster 遇到慢上传会等待而不是重新上传，每张图都要确认 X 连同 media ID 一起保存后才继续，并会清掉多余的图片块，所以导入结束后不应该留下重复。如果仍然看到，请在 X 里删掉多余的那张，并点击 **复制错误信息**（或复制证据包）：其中的 `trace` 会记录 xPoster 有没有发现并清掉多余的图片块，以及它们是什么时候出现的。

### 导入只成功了一部分

先不要发布。查看保存记录和诊断信息，找到失败步骤，然后用干净的 X Article 草稿重试。
